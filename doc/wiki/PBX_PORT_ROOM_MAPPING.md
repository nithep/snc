## ข้อเท็จจริงที่ต้องจำ (สำคัญ)

1. **เบอร์สถานี = เลขห้องโดยตรง (identity)** — ตู้ตั้งเบอร์ 1100-1127 ให้ตรงกับเลขห้องพักอยู่แล้ว จึง**ไม่ต้องแปลงค่า**: `pbx/room_map.json` ปล่อยว่างไว้ (fallback = ใช้เลขพอร์ตตามดิบ) หากอนาคตย้ายสาย/เปลี่ยนเบอร์ ให้เพิ่มรายการในไฟล์นั้น — hot-reload มีผลทันทีไม่ต้องรีสตาร์ท
2. **เบอร์ 1116 ไม่มีบนระบบ** — ลำดับข้ามจาก 1115 → 1117 (พอร์ต 033) แต่ Dashboard pre-populate ห้อง 1101-1127 จึงแสดงการ์ด "ห้อง 1116" ที่ไม่มีตัวตน (cosmetic เท่านั้น ไม่กระทบ KPI)
3. **เบอร์ 1100 = Master Console** (Grp 1) — SMDR รายงานเบอร์นี้เมื่อมีกิจกรรมที่คอนโซล Dashboard แสดงเป็น "สถานีพยาบาลหลัก (KEY-1100)"
4. **data SLT (Grp 32) ไม่ใช่ห้องผู้ป่วย** — ถ้า SMDR รายงานกิจกรรมจากช่วงพอร์ตข้อมูลเหล่านี้ ถือว่าผิดปกติ ควรตรวจสอบตู้ (ดู playbook ที่ [[PBX_CONNECTIVITY_TROUBLESHOOTING]])
5. **หน้า Offline ของ Config Builder แสดงค่า default (1001-1028) ไม่ใช่ config จริง** — ต้องเชื่อมแบบ Online → Read แล้วจึงอ้างอิงได้ (บทเรียน: เคยหลงใช้ค่า Offline ตั้ง map ผิดมาแล้ว 1 ครั้ง)
6. SMDR รายงานเฉพาะ*เบอร์สถานี* ไม่มีชื่อห้อง — การแปลงเป็นเลขห้องเกิดฝั่ง SNC เท่านั้น (การกรอก P092 Ext Name ใน Config Builder เป็นประโยชน์เชิงเอกสารในตู้เท่านั้น)

## กลไกฝั่ง SNC (อ้างอิง)

- Listener ใช้ `station_ext` (เบอร์ที่โทรออก) เป็นห้องเสมอ ไม่ใช่ group code หลัง `e.` — ดูเหตุผลใน `pbx/snc_pbx_listener.py` (`parse_smdr_line`)
- จุดแปลงค่าอยู่ที่ `_create_event_payload` → `load_room_map()` (hot-reload จาก `SNC_ROOM_MAP` หรือ `pbx/room_map.json`)
- Event จาก PBX จริงติดแท็ก `source: real` / ปุ่มจำลองติดแท็ก `demo` — KPI นับเฉพาะ real (แนวคิดกัน event หาย/ซ้ำ ตาม [[0004-outbox-idempotency]])
