# 🧪 Checklist — ทดสอบระบบหน้างานร่วมทีม (Field Test)

**อัปเดต:** 13 ส.ค. 2569 | **ผู้เข้าร่วม:** ช่างเทคนิค + พยาบาลตัวแทน + ผู้ดูแลระบบ
**ระยะเวลา:** ~1 ชม. (แบ่งเป็น 4 ช่วง)
**วัตถุประสงค์:** ยืนยันว่าระบบพร้อมวางจำหน่าย — ผ่านเกณฑ์นี้ครบ = ผ่านการรับรอง

---

## 📋 ก่อนเริ่ม (เตรียมการ)

- [ ] แจ้งหัวหน้าพยาบาลเรื่องการทดสอบ (มีสายเรียกทดสอบจากห้องจริง)
- [ ] เตรียม API Key สำหรับทดสอบปุ่มรับเรื่อง/เคลียร์
- [ ] เปิด dashboard ที่ห้องพยาบาล: https://snc.nithep.com
- [ ] ตรวจ pill เชื่อมต่อ = **เขียว "เชื่อมต่อสด"**
- [ ] ตรวจ services บน Pi:
  ```bash
  ssh pi4 'systemctl is-active snc-backend.service snc-pbx-listener.service'
  # คาดหวัง: active\nactive
  ```
- [ ] บันทึกเวลาทดสอบเริ่มต้น + ชื่อผู้ทดสอบ

## 🟡 ช่วงที่ 3 — กรณีพิเศษ / Resilience

| # | ขั้นตอน | ผลคาดหวัง | ผ่าน/ไม่ผ่าน |
|---|---------|-----------|:---:|
| 3.1 | กดเรียก 2 ห้องพร้อมกัน | Dashboard แสดงทั้ง 2 บัตร + แบนเนอร์มี 2 ห้อง | ☐ |
| 3.2 | รีสตาร์ต backend กลางอากาศ (`sudo systemctl restart snc-backend.service`) | Dashboard auto-reconnect กลับเขียว < 60 วิ | ☐ |
| 3.3 | ปิดเน็ต Wi-Fi ที่ห้องพยาบาล 30 วิ | pill เปลี่ยน amber/แดง → กลับเขียวเอง (reconnect อัตโนมัติ) | ☐ |
| 3.4 | เปิดหน้า dashboard พร้อมกัน 2 เครื่อง | ทั้ง 2 เครื่องเห็นเหตุการณ์พร้อมกัน (WS broadcast) | ☐ |
| 3.5 | ลองปุ่ม demo (ถ้าเปิดโหมด demo) | จำลองเหตุการณ์ขึ้นถูกต้อง | ☐ |
