# SOP — การ Power Cycle ตู้ Phonik PBX (แก้ session ค้าง)

**อัปเดต:** 13 ส.ค. 2569 | **ผู้ใช้:** ช่างเทคนิคหน้างาน / ผู้ดูแลระบบ
**ตู้:** Phonik PBX (192.168.1.91) | **ผลลัพธ์หลังทำ:** Listener ต่อกลับเองอัตโนมัติ 100%

---

## ⚠️ ข้อควรระวังก่อนเริ่ม

- **ผลกระทบ:** การปิดตู้จะตัดโทรศัพท์ภายใน/สายเรียกชั่วคราว (~2-3 นาที) — **แจ้งหัวหน้าพยาบาลก่อนทำ**
- **ห้าม** power cycle ตู้บ่อยเกิน 1 ครั้ง/10 นาที (กันตู้เสียหาย)
- ยืนยันก่อนว่าจำเป็น: ดูจากอาการด้านล่างก่อน

---

## 🔍 ควรทำ power cycle เมื่อใด?

| อาการ | วิธีเช็ค |
|-------|---------|
| `Connection refused` ที่ :23 (Pi + PC ทั้งคู่) | `telnet 192.168.1.91 23` → ติดต่อไม่ได้ทั้ง 2 เครื่อง |
| ตู้ตอบ `Not have free PABX telnet port` | ดูจาก log listener (`pbx_listener.log`) |
| Dashboard ค้าง offline นาน > 5 นาที + ระบบไม่ recover | ดู pill สถานะเชื่อมต่อ |
| หลังเปิด session ค้างไว้หลาย session | ตรวจว่ามีเครื่องอื่นแย่ง session อยู่ (ลองข้อนี้ก่อน power cycle) |

> 💡 **ลองง่ายก่อนเสมอ:** ถ้าเป็นเพราะมี session อื่นค้าง ให้ปลด session นั้นก่อน — power cycle เป็นทางสุดท้าย

---

## 🛠️ ขั้นตอน Power Cycle (ใช้เวลา ~3 นาที)

### ขั้นที่ 1 — เตรียมการ (ก่อนปิด)
```bash
# 1. บันทึกสถานะระบบก่อนทำ (จากเครื่องผู้ดูแล)
ssh pi4 'systemctl is-active snc-backend.service snc-pbx-listener.service'

# 2. เปิดดู log listener แบบ real-time (หน้าจอที่ 1)
ssh pi4 'tail -f /home/ecs-agent/nithep/snc/pbx_listener.log'
```

### ขั้นที่ 2 — ปิดตู้
1. ไปที่ตู้ Phonik PBX (192.168.1.91)
2. **ปิดสวิตช์ไฟตู้** (หรือดึงสายไฟ)
3. **รอให้ครบ 15 วินาที** (สำคัญ: เคลียร์ RAM + TCP stack ให้เต็มที่)

### ขั้นที่ 3 — เปิดตู้ + รอเชื่อมต่อ
1. เสียบไฟ/เปิดสวิตช์กลับ
2. รอตู้บูต (~1-2 นาที)
3. **ห้าม**เปิด session telnet จาก PC เพิ่ม — ปล่อยให้ Pi ต่อก่อน
4. สังเกต log listener: ควรเห็น
   ```
   Connected successfully to Phonik PBX!
   PBX authentication & SMDR subscription handshake completed
   ```

### ขั้นที่ 4 — ตรวจสอบผล
```bash
# 1. Services ทั้งคู่ active
ssh pi4 'systemctl is-active snc-backend.service snc-pbx-listener.service'
# คาดหวัง: active\nactive

# 2. Dashboard กลับเป็น เชื่อมต่อสด (เขียว)
# เปิด https://nursecall.nithep.com ตรวจ pill สถานะ WS

# 3. ทดสอบสายจริง: กดปุ่มเรียกที่ห้องใดห้องหนึ่ง → ควรขึ้นบน dashboard < 3 วินาที
```

### ขั้นที่ 5 — บันทึกผล
- บันทึกลง log งานช่าง: เวลาปิด-เปิด, ผลการเชื่อมต่อ, สาเหตุที่ต้องทำ
- ถ้าปัญหาเกิดซ้ำบ่อย (> 2 ครั้ง/สัปดาห์) → แจ้งผู้ดูแลระบบหาสาเหตุเชิงลึก

## 🏁 Handshake ที่คาดหวังหลังเปิดตู้ (ยืนยันว่าเชื่อมต่อถูกต้อง)

| คำสั่งที่ listener ส่ง | คำตอบจากตู้ | ความหมาย |
|---|---|---|
| `..tcmd=1` | `==tcmd=1` | เข้าโหมดคำสั่ง ✅ |
| `..VERS=` | `==VERS=DX-COMPACT V5.4r1 (V5.1r0)` | รู้เวอร์ชันตู้ ✅ |
| `..PASS=***` | `==ACKW` | ยืนยันรหัสผ่าน ✅ |
| `..EVNT=ALL` | `==EVNT=END` | รับ SMDR stream ✅ |

## ❓ ถ้าหลัง power cycle ยังไม่เชื่อมต่อ

1. รออีก 2 นาที แล้วดู log ซ้ำ (ตู้อาจบูตช้า)
2. เช็ค `ping 192.168.1.91` — ถ้าไม่ตอบ แสดงว่าไฟ/สายขัดข้อง
3. เช็คว่า Pi ยังเชื่อม LAN อยู่ (`ping` จาก Pi ไปตู้)
4. ตรวจ SMDR Target IP ในตู้ = `192.168.1.94` (ถ้า "เชื่อมต่อแต่ไม่มีข้อมูลไหล")
5. รายละเอียดเพิ่มเติม: `doc/wiki/PBX_CONNECTIVITY_TROUBLESHOOTING.md`
