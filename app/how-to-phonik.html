วิธีติดตั้ง SNC บน Phonik PBX

เผยแพร่ 20 ส.ค. 2569 · โดย นิเทพ เชิญสวัสดิ์ (Nithep Choensawat) · อ่าน 9 นาที

คู่มือทีละขั้นตอนในการดัดแปลงตู้สาขาโทรศัพท์ Phonik PBX (DX-32C/80C/144C) และบอร์ด Help Call ให้ทำงานเป็นระบบแจ้งเตือนพยาบาลเรียลไทม์บน Raspberry Pi 4 — รับ SMDR Log ผ่าน Telnet แปลเป็นมาตรฐาน HL7 FHIR และวัด SLA บน Dashboard

0. คุณสมบัติต้องมี (Prerequisites)

  • ตู้ Phonik DX-32C / DX-80C / DX-144C ที่เปิดพอร์ต LAN ได้ (ค่าโรงงานมักเป็น 192.168.1.91:23)
  • บอร์ด Help Call (Call Station v.107) + อุปกรณ์ห้อง (NCX-CORD / NCX-PULL / NCX-LED) ต่อเข้าตู้แล้ว
  • Raspberry Pi 4 (แนะนำ 2GB+), การ์ด microSD 16GB+, power supply
  • สาย LAN + (แนะนำ) Micro-USB to Ethernet Adapter เชื่อมตรงเข้าตู้ PBX
  • Raspberry Pi OS (Lite) + Python 3.12

รายละเอียดการเดินสาย/Config Builder ฉบับเต็มดูที่ doc/wiki/phonik_nurse_call_knowledge.md (จากคู่มือ Phonik + ผัง NC)

1. ภาพรวมสถาปัตยกรรม

[ห้องผู้ป่วย NCX-*] → ตู้ Phonik PBX (192.168.1.91:23) → (Telnet SMDR "==SMDX... e.400 ...") → Raspberry Pi 4 : snc_pbx_listener.py → FastAPI + SQLite (nurse_call_events.db) + WebSocket → Nurse Station Dashboard (เขียว/แดงกะพริบ/เหลือง) + Telegram

1.1 ระบบ SOS CALL (Emergency Call) — บูรณาการวัดผล

นอกจาก Nurse Call ปกติ SNC ยังรองรับ ระบบ SOS CALL (ระบบเรียกขอความช่วยเหลือฉุกเฉิน) ที่เหมาะกับพื้นที่ต้องการรักษาความปลอดภัย เช่น หน่วยงานราชการ ห้องตรวจรักษา ลานจอดรถ — มีทั้งไฟเตือนและเสียงเตือน

อุปกรณ์หลักของ SOS CALL

  • DX-SOS (SOS Station): เครื่องเรียกฉุกเฉิน มีปุ่มกด + ไฟสถานะ สนทนากับ Master Console ได้
  • NCX-LED: ไฟแอลอีดีติดค้างเมื่อมีการเรียก จนกว่าห้องควบคุมจะสั่งปิด
  • NCX-BUZ (Buzzer): ส่งเสียงดังเมื่อเรียก และ หยุดทันทีเมื่อห้องควบคุมรับสาย (ไม่รบกวนการสนทนา)
  • PI-32G (Master Console): ตอบรับ/เรียกแต่ละเครื่อง มีไฟเตือนค้างจนกว่าจะ "ดับไฟ" เมื่อเสร็จงาน
  • NCX-N-DSP (จอ 4 บรรทัด) / NCX-B-DSP (จอ 1 บรรทัด): แสดงหมายเลขสเตชั่นที่เรียกมา
  • MDF90 / MDF180: กล่องพักและกระจายสาย · DX-8ATI สูงสุด 3/6/8 แผง (DX-32C/80C/144C)

ความจุสูงสุด: (PI-32G)+(DX-SOS)+(NCX-B-DSP)+(NCX-M-DSP) = 24+2 / 48+2 / 64 · DX-SERIES Version V.6.4rl

วิธีที่ SNC วัดผล SOS CALL

เมื่อเกิด SOS ตู้ Phonik จะพ่น SMDR เหตุการณ์ e.{room_id} แบบ EC (Emergency Call) — SNC จับเวลาเกิดเหตุ เปลี่ยน Dashboard เป็น แดงกะพริบ ทันที และเริ่มจับ Response Time จนกว่าจะ Acknowledge/Clear ที่ Master Console ผลลัพธ์ (เวลาตอบสนอง, SLA Level 1–3) ถูกบันทึกลง SQLite (FHIR JSON) นำไปทำรีพอร์ตพรีเมี่ยมรายวัน/รายเดือนได้ — นี่คือการ "บูรณาการกับระบบ SOS วัดผลการเรียก" โดยไม่ต้องเดินสายเพิ่ม

2. เตรียมฮาร์ดแวร์ Edge (Pi 4)

1

เชื่อมเครือข่ายเข้าตู้ PBX โดยตรง

ต่อ Pi 4 เข้าสาย LAN เดียวกับตู้ Phonik (ผ่าน Switch หรือ Adapter) ให้ Pi อยู่ในช่วง IP เดียวกับ 192.168.1.x วิธีนี้ลดสัญญาณ Wi-Fi รบกวน ได้ Latency ต่ำและเสถียร

2

ตั้ง IP ให้ Pi ตรวจถึงตู้ได้

ทดสอบว่า Ping ถึง 192.168.1.91 ได้: ping 192.168.1.91 ต้องตอบกลับ

3. ติดตั้ง snc_pbx_listener

3

clone โปรเจกต์และเตรียม Python

รันบน Pi 4: ติดตั้ง dependencies แล้วตั้งค่า .env ให้ชี้ PBX_HOST=192.168.1.91 และ PBX_PORT=23

4

รัน Listener + TCP Proxy

สคริปต์มี TCP Proxy พอร์ต 2323 ในตัว เพื่อจำลอง Handshake ให้โปรแกรม Room Manager/PC Operator เดิมดึงประวัติได้พร้อมกันโดยไม่ขัดแย้งกับ SNC และมีกลไก Heartbeat + Auto-Reconnect (ตู้ตัดสายทุก ~60 วินาที) แก้ปัญหาสายขาดอัตโนมัติ

4. รัน Backend (FastAPI)

5

เปิด API + Dashboard

รัน api/server.py (FastAPI + SQLite WAL + WebSocket) หน้าแดชบอร์ดจะเสิร์ฟที่พอร์ต 8000 ฐานข้อมูล nurse_call_events.db จะถูกสร้างอัตโนมัติ

6

ตั้งเป็น systemd service (24/7)

ลงทะเบียน snc-backend.service และ snc-pbx-listener.service ให้เริ่มพร้อมบูตและมี Watchdog กู้คืนเอง

5. ทดสอบจริง

7

กด CALL / ดึงสาย NCX-PULL

ที่ห้องผู้ป่วย ให้กดปุ่มเรียกหรือดึงสวิทช์ฉุกเฉิน แล้วสังเกต Dashboard เปลี่ยนเป็น แดงกะพริบ ทันที

8

ตรวจ SMDR Log

ใน log ของ listener จะเห็นบรรทัดเช่น:

==SMDX2005=03/08/26 18:59 401 e.400 EC 0:00'09 0 #1

ซึ่งระบบสกัดเบอร์ห้อง 401 และ Event e.400 (ฉุกเฉิน) แปลงเป็น FHIR JSON ทันที

9

วัด Response Time / SLA

เมื่อพยาบาลกด Acknowledge/Clear ระบบจับเวลาตอบสนองและคำนวณ SLA Level 1–3 พร้อมรายงานรายวัน/รายเดือน

6. การแก้ปัญหา (Troubleshooting)

  • สายตัดทุก 60 วินาที: ปกติของตู้ Phonik — ระบบมี Heartbeat + Reconnect กู้คืนอัตโนมัติ ตรวจ log ว่ามี "reconnect" เกิด
  • โปรแกรมเดิมดึง log ไม่ได้: ใช้ TCP Proxy พอร์ต 2323 แทน โดยให้โปรแกรมเดิมต่อ 2323 SNC ต่อ 23
  • Dashboard ไม่ขึ้นแดง: ตรวจ Ping ถึง 192.168.1.91 และสถานะ service ว่า active
  • เวลาเพี้ยน: ตั้ง NTP บน Pi ให้ตรงเวลาโรงพยาบาล (SLA คิดจาก timestamp)

7. คำถามที่พบบ่อย (FAQ)

ต้องเดินสายใหม่ทั้งหมดหรือไม่?
ไม่ต้องครับ ใช้สาย LAN เดิมของตู้ Phonik และบอร์ด Help Call ที่มีอยู่แล้ว เพียงต่อ Pi 4 เข้าเครือข่ายเดียวกัน
ถ้าไม่มี Phonik ล่วงหน้าทำได้ไหม?
ได้ครับ ต่อบอร์ด Help Call เข้า Pi 4 โดยตรง หรือประเมินร่วมกับทีมงานเพื่อออกแบบให้เหมาะสม
ข้อมูลเก็บที่ไหน?
SQLite ในเครื่อง Pi มาตรฐาน HL7 FHIR รองรับนำส่งระบบภายนอก/ผู้กำกับดูแลได้
เสถียรพอสำหรับ 24/7 หรือไม่?
ได้ครับ มี systemd + Watchdog + Auto-Reconnect รักษาสายตลอดเวลา
รองรับระบบ SOS CALL ฉุกเฉินหรือไม่?
รองรับครับ DX-SOS + NCX-BUZ/NCX-LED จะถูกจับเป็นเหตุการณ์ EC SNC แสดงแดงกะพริบและวัด Response Time จนกว่าจะ Clear ที่ Master Console

ต้องการให้ทีมงานติดตั้งให้?

ส่งรุ่นตู้ Phonik และจำนวนเตียง ให้ทีมงานประเมินและติดตั้งบูรณาการรวมถึงรายงานพรีเมี่ยม
